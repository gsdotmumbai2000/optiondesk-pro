# Python Development Rules

- Use Python best practices and clean, readable code.
- Follow PEP 8 where practical.
- Prefer clear type hints for function parameters and return values.
- Do not modify unrelated files.
- Before making a major change, explain which files will be changed and why.
- Preserve existing project architecture and coding patterns.
- Reuse existing functions and components where appropriate.
- Do not introduce unnecessary dependencies.
- Add appropriate error handling and logging where required.
- When fixing a bug, identify the root cause before proposing the fix.
- For complex changes, break the work into small logical steps.
- When modifying existing code, avoid changing public behavior unless explicitly requested.
- Add or update tests when practical.
- Never expose passwords, API keys, tokens, or other secrets in source code.
- Clearly mention assumptions when project requirements are ambiguous.
